
# 操作教程 —— 从零到顺手

> 面向第一次拿到这个包的人：**装上 → 连通 → 会用 → 会排错**，全程约 40 分钟（熟练后 5 分钟）。
> 当前版本：插件 **v3.3.0**（6 个模型工具）· Blender addon **v2.0.0 / protocol 12** · Gateway `127.0.0.1:39877`（addon 主动连接，无入站端口）。
> 前置条件（Blender + `DSH Blender Bridge` addon + Node ≥ 24.9 + DSH）见 [README `2](../README.md#2-前置条件4-条缺一不可)；GUI 通道要求 Blender 开着且 addon 已 Connect，后台作业不要求 GUI。
> 配置项（工作目录 / blender.exe / 端口 / 会话与作业超时）见 [配置参考.md](配置参考.md)。

## 0. 心智模型：先理解这 4 件事

1. **两条线并行**
   - **GUI 通道**：addon 主动连接 Gateway（WebSocket，默认 `127.0.0.1:39877/addon`）；毫秒级、实时，但**要求 Blender GUI 开着**，且所有命令串行占用它。`blender_session`（会话/权限）、`blender_op`（算子 / 内环 / 精简 / 配方）、`blender_py`、`blender_see`、`blender_inspect` 都走它；执行型 op 需要 ready 的 GUI 会话。
   - **后台作业**：`blender_run` 提交的一次性 `blender -b` 进程（`kind="headless"`）或声明式最终渲染（`kind="render"`）独立进程；**不占 GUI 通道**，可与 GUI 线同时跑。submit 立即返回 jobId，之后 status / wait / collect / cancel 收结果。
   - 3.1 **没有**持久 worker 会话、没有 `session` / `session="auto"` 参数、也不会自动降级到无头 —— 需要无头就在 `blender_run` 里显式提交作业。
2. **四种"看"**（都由 `blender_see` 出图，语义不同）
   - `viewpoint="viewport"` 视口帧 = **用户正在看的角度**（含视口着色与覆盖物）；
   - `viewpoint="custom"` = **你指定的机位**（`from` + `look_at`，不建相机、不动用户视口）；
   - `viewpoint="camera"` = **当前帧的求值相机**（按渲染比例取景，不改 `scene.camera` / 帧 / 选择 / 视口）；
   - `full=true` = **整个 Blender 窗口**（看 UI / 面板 / 其他编辑器）；
   - `mode="sequence"` = 固定机位连续采样（最多 32 帧、逐帧 hash；**不执行代码**，只观察画面）。
3. **内环 vs 外环**：模型回合（几秒）贵，Blender 事件循环（160 tick/s）便宜 →
   **搜索放 Blender 侧（`blender_op(action="loop", …)`），决策与验收放模型侧**。详见 [假设驱动建模 cookbook](假设驱动建模-cookbook.md)。
4. **会话归属与写权限**：GUI 会话有归属与写 scope。`blender_session` 负责 `attach/claim`（附着 / 认领）、`grant/revoke`（把 `exclusive` / `collection:名` / `prefix:名` / `object:名` 写权限授予子 agent）、`mark_read`（清掉 human_modified 冲突）；`pause/resume` **只有人类能操作**（agent 调用返回 `human_action_required`）。Gateway 进程与 Blender 启动由 DSH 宿主管理，模型面**没有** lease / launch / restart 这类通道运维动作。
   - **子 agent 有自己的 dshSessionId**：父会话 attach 后，子 agent 可以 `attach` 成 **viewer**（只登记 presence，不夺 owner；回执顶层带 `viewer / is_mine / borrowed`）；宿主不发 `x-dsh-parent-agent-id` / `role` 不可靠时，**同机任意非 owner** 都可 attach 成 viewer（`is_mine=false`，只读）。父 agent 的 grant 只给 `target_agent_id` 就够（holder 按 hostId+agentId 匹配），grant 覆盖的 scope 才放行写。**写调用不需要 attach**：grant 命中即可直接 `blender_py`；attach 只影响 presence / 只读可见性。
   - **同机只读可见**：别人的会话会出现在 `list` 里，带 `owner` / `is_mine=false` / `borrowed=true`；`blender_see` 与只读 op 可以直接用，回执 `source.is_mine=false` 说明这不是你的场景。写操作没有 grant 一律 `session_in_use`。
   - **僵尸租约**：owner 记录带 `role` 与心跳年龄；子 agent owner 30 s 没心跳即失效，**主 agent 30 分钟**（等一轮子代理不会被夺权；任何 blender_* 调用也会续心跳）。`prune` 自动回收（有活跃 `blender_py` 时不动），但**不再连 grants 一起清**——grant 有自己的 TTL。`list/status` 会显示 `heartbeat_age_ms` / `stale_after_ms` 与一条 `release ... force=true`；同机主 agent 也可直接 `force=true` 释放。
   - **grant TTL**：默认 10 min，`ttl_ms` 可到 1 h；`expiresInMs` 是真实剩余值。被 grant 覆盖的写操作会按原 TTL 续期。

> 方法论：证据不足时如何明确报 unresolved、用探针翻转假设、把"为什么这么建模"写清楚 —— 见 [假设驱动建模 cookbook](假设驱动建模-cookbook.md)。

### 什么时候用哪个工具

| 你要做的事 | 用哪个 | 为什么 |
|---|---|---|
| 看一眼现在长什么样 | `blender_see`（`viewpoint="viewport"`） | 50–160 ms，最便宜；GUI 会话在线即可 |
| 换个角度看（不想动用户视口） | `blender_see`（`viewpoint="custom", from, look_at`） | 零场景改动，可重复（md5 稳定） |
| 用场景相机的构图看 | `blender_see`（`viewpoint="camera"`） | 当前帧求值相机 + 渲染比例，不改场景 |
| 改一步就想验证 | `blender_py(code=…, see=True)` | 一个原子步 ≈105 ms；GUI Python 固定 exclusive |
| 判断"动没动 / 对不对" | `blender_see`（`mode="sequence", seconds, fps`） | 时间窗连续采样 + 逐帧 hash，一次最多 32 帧 |
| 搜索 / 拟合参数（几千次迭代） | `blender_op(action="loop")` | 内环跑在 Blender 侧，不花模型回合 |
| 多目标 + 约束的测量 | `blender_op(action="loop")` + `penalize` | 罚项把违规量并入单一 score |
| 收敛后复核 / 复用 | `blender_py` 复算 + `blender_op(action="loop", op="export")` | 防"只优化了你写的目标函数" |
| plan 判定 / 验收 / 导出 | `blender_op(action="plan", op=…)` | 38 family / 270 op 的唯一入口；执行型要 GUI 会话 |
| Cycles 成品渲染 / 相机动画 | `blender_run(action="submit", kind="render", …)` | 声明式、异步、有界队列 |
| 大批量几何 / 校验 / 长脚本 | `blender_run(action="submit", kind="headless", …)` | fresh `blender -b` 进程：不占 GUI、超时可杀 |
| 长活 / 批处理（>100 s） | `blender_run` submit → wait / collect | 返回 jobId，超时不丢结果 |
| 多视角 QC / 成品出图 | `blender_op(op="qc_render_views")` 或 `blender_run(kind="render")` | 自动取景 + 三点光 + 逐张 md5；分钟级走作业 |
| 参考图量尺寸 / 标定 | `blender_op(op="img_digest / img_probe / img_measure / img_calib")` | 把"看不清"变成数字表，不靠眼睛估 |
| 装配合并 / 穿模 / 修复 / 交付 | `blender_op(op="asm_*")` | manifest 驱动 + verdict 三态 + gate 后再导出 |
| 白模 / Seedance 参考包 | `blender_op(op="blockout_*")` | 声明式 parts + 4 视图 PNG / 拼图 + MP4 转台 |
| 同机位 QC 一页 verdict | `blender_op(op="visualreport_report")` | IoU / 缺多面积 / 缺陷 crop + mm 定位 |
| 按参考图反推尺寸 | `blender_op(op="shapesolve_solve")` | 多视轮廓拟合，不渲染、不依赖 timers |
| 缺陷评估（插件抓不抓得住） | `blender_op(op="eval_run")` | 合成缺陷集 capture_rate + 基线回放 |
| 开工体检 / 回退点 / 强制交付 | `blender_op(op="gate_*")` + `blender_session(action="txn")` | 不过门不导出；drill 进交付流程 |
| 渲染慢要调参 | `blender_run(action="tune", op="status"→"analyze"→"apply")` | 先量后调；预设可 revert |
| 场景对象太多导致每轮同步慢 | `blender_op(action="opt", op="analyze"→"join")` | ≈1.4 ms/对象；几何零损失，务必先存回退点 |
| addon 只读命令 / 命令面 | `blender_inspect(command=…)` | help 只列可执行只读命令；写命令会指路 |
| 出错不知卡在哪 | `blender_session(action="doctor")` | 真跑一次 bpy 往返 + 三级判定 + 修法 |
| virtual-gui 起不来（缺 Xvfb/VirtualGL/helper） | `/blender doctor --fix` | 只安装缺失前提；不装依赖不启动，也不回落 headless |
| 多个会话抢同一个 Blender | `blender_session(action="grants"/"status")` | 看持有者与写权限；用完 release / revoke |

## 1. 安装与连通

### 1.1 Blender 侧：装 addon 并 Connect

1. 在 Blender 里打开 `Edit ▸ Preferences ▸ Extensions ▸ Install from Disk...`，选 `dsh_blender_bridge.zip`（Blender 扩展包，模块名 `bl_ext.user_default.dsh_blender_bridge`）。
2. 启用它（勾选 checkbox）。
3. 打开一个 **3D 视图**，按 `N` 打开右侧栏 → 找到「DSH Blender Bridge」面板 → 点 **Connect**（addon 主动连接 Gateway；默认 39877）。
4. 面板里可顺手打开需要的集成（PolyHaven / Hyper3D / Sketchfab / Poly Pizza / Hunyuan3D）；**这些开关是 scene 属性** —— 改完记得存进你的 startup / 工程文件（重启 Blender 会丢未保存的）。

> ⚠️ **addon 迁移**：只支持本仓 `DSH Blender Bridge` **v2.0.0 / protocol 12**。旧的 `MCP for Blender` / `blender_mcp` **已不再支持**，请先停用旧 addon 再安装/启用本仓 addon（3.1 addon 主动外连 Gateway，不占 9876 入站端口；但旧 MCP 桥仍可能监听 9876，不能同时开）。迁移要点见 [../MIGRATIONS.md](../MIGRATIONS.md)。

> 判断 addon 是否已连接：在终端跑 `curl -sS http://127.0.0.1:39877/doctor`；或直接 `node lib/runtime/_probe_tools.js` 看 Gateway 实例与命令面。

### 1.2 从 npm 安装插件（普通用户）

普通用户不需要 clone 或构建；npm 包自带构建后的 `lib/`。

```bash
dsh plugin --profile <profile> add dsh-blender-plugin@3.3.0
dsh --profile <profile> --dump-config | grep -A3 dsh-blender-plugin
# 然后重启 DSH
```

> DSH Desktop 用户可以在 Plugins 页面安装 bundle `dsh-blender-plugin@3.3.0`。
> 不需要同时使用"运行时注入"与"bundle 装配"：两个 fiber 会重复注册同名工具。

### 1.3 从源码构建（开发者）

只有修改插件源码时才需要：

```bash
git clone https://github.com/sixtysevenlf/dsh-blender-plugin.git
cd dsh-blender-plugin
npm ci --legacy-peer-deps && npm run build   # 构建 lib/ 与 lib/runtime/
```

装进 profile 用一条命令（自动解析 profile、只复制变化的文件、不碰 `runtime/ext`、写 profile 触发 HMR、自证 /health + /status + catalog）：

```bash
npm run dsh:link       # 开发模式：profile 依赖切成 link:<repo>；之后改完 npm run dsh:reload（~6 s）
npm run dsh:install    # 发布形态：按 npm 包文件清单覆盖安装目录
npm run dsh:verify     # 只验证，不装
npm run dsh:install -- --with-addon   # 顺带把 Blender 扩展放进 user_default（免 Install from Disk）
```

手工方式（等价，排错时用）：`node_modules/dsh-blender-plugin` 建 junction，
profile 的 `dependencies` 加 `"dsh-blender-plugin": "link:<本目录绝对路径>"`，
`dsh.profile.bundles` 加 `"dsh-blender-plugin"`，再 `--dump-config` 预演并重启 DSH。
细节与实测数据见 [安装与升级-加速方案.md](安装与升级-加速方案.md)。

### 1.4 后端自检（三条命令）

```bash
curl -sS http://127.0.0.1:39877/health   # {"ok":true,...}    后端进程活着
curl -sS http://127.0.0.1:39877/doctor   # ⭐ kind=ok 才算"Blender 也连上了"
curl -sS http://127.0.0.1:39877/who      # 会话 + 写权限租约 + 通道指标 + 当前生效配置
```

**唯一验收判据**：`/doctor` 返回 `kind=ok`（或 `blender_session(action="doctor")` 的 `kind=ok`）。其它自检失败只说明那一项功能有问题，**不能替代**这条验收。

DSH TUI 里直接跑 `/blender doctor`；加 `--fix` 会读取 `/doctor` 的 `virtualGui.installPlans`，显示并引导安装 virtual-gui 前提（发行版矩阵与一键范围见 [配置参考 §5.7.1](配置参考.md)）。

`/doctor` 返回里的关键字段：

| 字段 | 含义 |
|---|---|
| `kind` | `ok` / `blender-unreachable` / `main-thread-busy` / `addon-thread-stuck` / `addon-unresponsive` / `addon-error` |
| `summary` `fix` | 一句结论 + 一句修法（直接照着做） |
| `ping_ms` `roundTripMs` | `ping`（不碰 bpy）与 `status`（真跑 bpy）的耗时 |
| `config` | **当前生效配置**：工作目录、blender.exe、端口、配置文件来源 —— 排错先看它 |

### 1.5 插件工具自检

```text
blender_session(action="doctor")          # 同 /doctor，但在工具回执里更可读；kind=ok 是唯一验收判据
blender_op(op="catalog")                  # 应为 38 个 family / 270 个 op（6 个模型工具）

blender_see(max_size=560)                 # GUI 在线时：应返回一张图，50–100 ms
blender_run(action="submit", kind="headless", script="print('HEADLESS {ok:true}')")
                                          # 纯后台时：返回 jobId → action=wait/collect 收结果
```

## 2. 六个工具逐个上手

> 约定：所有工具都要求**后端在跑**（插件自动拉起）。
> GUI 通道工具（`blender_session` 的多数动作、`blender_op` 执行型 op、`blender_py`、`blender_see`、`blender_inspect` 命令）需要 **ready 的 GUI 会话**：用户在 Blender 里 Connect，或 `blender_session(action="attach")` 附着他已打开的会话。
> 不需要 GUI 会话的：`blender_op` 的 `catalog` / 只读 op / `args.dry_run=true`（本地或 Gateway 只读路径，也不会启动 Blender），以及 `blender_run` 的作业提交（fresh `blender -b` / 声明式渲染）。白名单 op（`audit_mesh` / `img_*` / `visualreport_report` / `qc_render_views` / `montage`）+ `args.file` 走本地无头车道；加 `headless=true` 则**有 GUI 会话也强制无头**（并发建模不抢单实例 GUI）。
> 参数名用工具 schema 里的原名（WSL / Windows 通用）；3.0 旧工具名见下表迁移。

### 从 3.0 工具名迁移

| 3.0 | 3.1 |
|---|---|
| `blender_rt_see` | `blender_see` |
| `blender_rt_watch` | `blender_see(mode="sequence")`（`code=` 移到 `blender_py`） |
| `blender_rt_do` | `blender_py`（`session/preload/auto/view_size` 移除） |
| `blender_rt_plan` | `blender_op(action="plan", …)`（`op/args/path/attach_images` 不变） |
| `blender_rt_loop` | `blender_op(action="loop", …)` |
| `blender_rt_opt` | `blender_op(action="opt", …)` |
| `blender_rt_preset` | `blender_op(action="preset", …)` |
| `blender_rt_perf` | `blender_run(action="tune", …)` |
| `blender_rt_headless` | `blender_run(action="submit", kind="headless", …)`（异步；wait / collect 收） |
| `blender_rt_job` | `blender_run(action="submit" \| "status" \| "wait" \| "collect" \| "cancel" \| "list")` |
| `blender_rt_cmd(name=X, params=Y)` | `blender_inspect(command=X, args=Y)` |
| `blender_rt_commands` | `blender_inspect()`（默认 help） |
| `blender_rt_txn(op=O, …)` | `blender_session(action="txn", op=O, …)` |
| `blender_viewport` | `blender_session`（status / doctor / presence；lease / launch / restart 由宿主管，不是模型工具） |
| `blender_rt_worker` | 3.1 不是模型工具：GUI Python 用 `blender_py`；后台 / fresh 场景脚本或渲染用 `blender_run(kind="headless" / "render")` 提交 + wait / collect |

### ① `blender_session` —— 会话 / 归属 / 权限 / 事务

| 参数 | 说明 |
|---|---|
| `action`（必填） | whoami / list / status / doctor / attach / claim / detach / release / grant / revoke / grants / pause / resume / mark_read / presence / heartbeat / start / stop / consent_request / consent_status / consent_approve / consent_deny / txn / reload / help |
| `request_id` | 只读引用：consent_status 回的请求 id（来自 start 的 `consent_required` 回执）。**批准/拒绝不在工具面**：人点会话面板（`handle`）或在终端跑回执里的命令 |
| `wait_ms` | start：等人类批准的最长毫秒（默认 20000，0=不等待直接回 `state=pending`，上限 120000） |
| `session_id` | 会话 id（大多数会话级动作必填） |
| `instance_id` | attach / claim 时的 addon 实例 id（多实例必填；`status` 里能看到 `instanceId`） |
| `kind` | start 的会话类型，只接受 `virtual-gui` |
| `scopes` | grant / mark_read 的 scope 列表：`exclusive`、`collection:COL`、`prefix:OBJ_`、`object:Cube`；多个用逗号分隔 |
| `target_agent_id` / `target_dsh_session_id` / `target_host_id` | grant 的目标（同 DSH session / 跨 DSH session / 跨 host） |
| `grant_id` | revoke 的授权 id |
| `ttl_ms` | grant 有效期毫秒（默认由 Gateway 决定） |
| `op` `label` `note` `objects` `keep` `into` `backup` | txn 子动作参数（见下表） |
| `force` | 保留参数：由 Gateway 决定是否接受强抢语义 |

| action | 作用 | 要点 |
|---|---|---|
| list / status / doctor | 看会话 / 实例 / 通道 | `doctor` 真跑一次 bpy 往返 + 三级判定，`kind=ok` 是唯一验收判据 |
| whoami | 回本调用者的 `agentId / dshSessionId / hostId / role` | 子 agent 拿真实 UUID 去发 grant，不用先失败一次；不依赖任何会话 |
| attach / claim / detach / release | 附着 / 认领 / 脱离 GUI 会话 | 多实例必须给 `instance_id`；`claim` 认领会话所有权；子 agent（独立 dshSessionId + `parentAgentId`=owner）attach 成 viewer。`release` **不会静默成功**：无此会话 → `session_not_found`，owner 被别人持有 → `session_in_use`（**同机主 agent 可 `force=true`**；stale owner 自动回收），owner 心跳过期但你仍在该会话的 agents 里 → 真的释放（`released=true, reason=owner_expired`） |
| grant / revoke / grants | 写 scope 授权 | 把 `exclusive` / `collection:名` / `prefix:名` / `object:名` 授予子 agent；`revoke` 按 `grant_id` |
| pause / resume | 暂停 / 恢复 AI 操作 | **human-only**：agent 调用返回 `human_action_required`，让用户在 N 面板点 |
| mark_read | 清掉 `human_modified` 冲突 | 人改过场景、你确认已读后清标记 |
| presence / heartbeat | 在场 / 心跳 | 多 agent 面板显示；长任务期间可主动心跳 |
| start / stop | virtual-gui 会话 | manual 策略下 `start` 落一条待批准请求并**等人类在会话的「Blender 会话」面板点批准**（默认 20 s）；批准后**同一次调用**就成功（`consent_source=approved_request`），超时回 `state=pending`，再 `start` 一次即消费（只消费一次）。**user-gui 永远由用户自己打开 Blender 并启用扩展（addon 主动拨入，无需点 Connect）** |
| consent_request / consent_status | 本 agent 的同意请求 | 看还有哪些待批准；`start` 会自动生成一条（15 分钟内复用） |
| ~~consent_approve / consent_deny~~ | **人类动作，已从工具面移除** | agent 调用回 `consent_human_only`；带 DSH 身份的 HTTP 调用同样 403。人在会话面板点按钮，或终端 `GET /lease?action=consent_approve&handle=…` / `requestId=…` |
| txn | 事务快照 / 回滚 | 见下表 |
| help | 帮助 | |

> **release 的可见性（2026-11-20 现场）**：owner 心跳过期（主 30 min / 子 agent 30 s）会被 prune 清成 `owner=null`，但 agents 与 grants 仍留着；此时 `status` 标 `owner_expired → re-attach`，`grants` 不再误报 `session_in_use`，重新 attach 后 grant 仍在。旧实现会清 grants 并回 `{"ok":true,"released":false}`；现在失败一律回 `ok=false` + `reason`（`not_found` / `owner_mismatch` / `owner_expired`），不再用成功信封包一个"什么都没做"。

`status` 同时打印 `provenance`（loaded/current/verdict）与 `runtime modules`（loaded_hash / disk_hash / verdict）。后者对账已注入的 `runtime.py.*` 模块：热更后如果模块还是旧源，会显示 `verdict=stale`；下一次对应 op 会按模块文件树指纹自动清缓存并重注，不需要手 reload。

`list` / `doctor` 自带**本地环境证据**（工单 6）。稳定契约是路由 `GET /status?evidence=1&evidenceOnly=1`（list 就取这一份，不付 addon 往返）：

```text
local_evidence.sessions          []                                       # 未认领时长度 0
local_evidence.local_processes   [{pid, name, role, port}]               # role: gateway|worker|addon|win_proxy|other
local_evidence.ports             [{port, listening, pids[], pids_raw[], process, role, mode}]  # 39877 / 9879；9877 是 3.0.x 历史端口
local_evidence.ports_evidence    {source: netstat|fixture, scanned_at: ISO8601, gateway, worker, legacy, conflicts[], reader}
local_evidence.degraded          bool                                     # 空数组必须 true + error
```

三条口径：

- 39877 的 `pid` 必须等于 Gateway 自己的 pid 才算 `matched=true`；9877（3.0.x 历史默认端口）只展示、不冒充 Gateway（`counts_as_gateway=false`）。Blender 进程归 `addon`（在 9879 上监听时归 `worker`），隐藏桌面 helper 归 `win_proxy`。
- `ports[].pids` 是**认定值**（只含通过归属判据的监听者）；原始监听行放 `ports[].pids_raw`（诱饵 pid 只会出现在这里）。`mode` 标 `fixture` / `live`，读者不用猜这份证据是回放还是现扫。
- `local_processes[].role`（工单 6d）：worker **注册表**里的 pid 一律 `worker`（不按映像名猜）；唯一未被 worker/gateway/proxy 认领的 blender 且 addon 在线才算 `addon`，识别不了的 blender 一律 `other`。worker 活跃时它绝不会再被标成 addon。
- 扫描失败不沉默：`degraded=true` + `error`，端口 `listening=false`（不是"关着"）；`netstat` / `tasklist` 各有超时与 512 KB 输出上限。
- `list=0` 只代表**未认领**：回执直接给 `next_actions · blender_session action=attach instance_id=<id>`；addon 状态与 `status` 同源（同一个 addon client），3.1+ addon 主动拨入 Gateway，不需要用户点 Connect。

注入点（回放 / 诊断用，不影响真环境）：

- `blender_session action=list probeFixture=<path>`：回放磁盘上的诱饵 fixture，`false_positives` 必须为空；样例在 `tests/fixtures/session/p6_decoy_ports.json`（部署副本：`…\node_modules\dsh-blender-plugin\tests\fixtures\session\p6_decoy_ports.json`）。回放的 `gatewayPid` 是**fixture 文件里的期望值**，不是现网 Gateway pid —— 判据是 `false_positives=[]`，不是 pid 与现网一致。
- `blender_session action=doctor forceNoAddon=true`（或设 `DSH_BLENDER_FORCE_NO_ADDON=1`）：不看 addon，仍给与 list 同源的 39877 证据与 `verdict`；`DSH_WORKER_PORT` 覆盖 worker 端口（默认 9879）。
- `/doctor` 认 `forceNoAddon=1` / `probeFixture=…` 两个查询键；`/status` 认 `evidence=1` / `evidenceOnly=1` / `probeFixture=…`。

`action="txn"` 子动作：

| op | 作用 |
|---|---|
| `snapshot` | 文件级快照（`label` / `note`），整场景可回退 |
| `restore` | 载入快照（`into="auto"` 默认落回快照出处文件；`"snapshot"` 非破坏只看一眼；`"original"` 必须能回写）；`backup` 默认先留 pre_restore 备份 |
| `list` / `prune` | 快照 + mark 清单 / 只保留最近 `keep` 个快照 |
| `mark` / `revert` / `marks` / `drop` | 对象级 mark / 就地回滚（只记 transform / 材质槽 / 可见性 / 修改器开关，毫秒级）；`marks` 列清单，`drop` 删除 |
| `help` | 完整契约 |

边界：对象级 **不含拓扑 / UV / 顶点级改动**（Boolean、合并、删面之后回不去）→ 用文件级 `snapshot/restore`。
`restore` 默认先备份：`backup=True` 先留 `_pre_restore_*` 快照，会话脏且要覆盖原文件时另留磁盘副本 `_pre_restore_file_*`。

```text
blender_session(action="status")
blender_session(action="attach", instance_id="…")          # 多实例时明确附着哪一个
blender_session(action="grant", target_agent_id="agent-2", scopes="object:Cube,prefix:Wheel_", ttl_ms=600000)
blender_session(action="grants")
blender_session(action="revoke", grant_id="grant-…")
# 子 agent 有独立 dshSessionId 时 target_agent_id 足够：holder 按 hostId+agentId 匹配，
# parentAgentId 记为授权者；ttl_ms 默认 10 min、上限 1 h，覆盖的写操作按原 TTL 续期。
# owner 心跳过期（owner=-）后主控仍能 grant：无主会话会先在这次调用里被重新认领；
# status/doctor/presence/grants/heartbeat/detach 都可以省略 session_id（按调用方自己的会话解析）。
# 旧 target 换了（显示名→真实 UUID）时用 force=true 替换重叠 grant；grant 不会锁住 granter 自己。
# 同机任意非 owner 都可以 attach 成只读 viewer（不需要 parent header）；写仍要 grant。
blender_session(action="txn", op="snapshot", label="before_join", note="Boolean 前")
blender_session(action="txn", op="mark", label="iter7", objects="Cube,Wheel_L")
… 改动 …
blender_session(action="txn", op="revert", label="iter7")  # 拓扑变过的对象会跳过并报告
```

> `txn` 的 `restore / mark / revert` 属写操作：需要 exclusive grant，且人类未暂停。
> **借读会话跑 `blender_py`**（is_mine=false、没有声明 `write_scope`）回 `scope_required` + "declare write_scope…"，不再是容易误解的 `session_in_use`；纯读请用 `blender_see` / `blender_inspect`。
> Gateway 进程与 launch 运维不在模型面 —— 启动/重启由 DSH 宿主管理；模型侧诊断只用 `action="status"/"doctor"`。

**attach 不再"假活"（3.2）**：`attach` / `claim` 现在先看 live 实例表，再做一次 addon `ping`。

| 回执 | 什么时候出现 | 怎么办 |
|---|---|---|
| `ok` + `status=ready` | 实例在表里且 ping 有应答 | 正常用 |
| `addon_disconnected` | 你的 Blender 掉线了（记录被 prune 释放，30 分钟内仍记得是哪个 instance） | 在 Blender 里重新 Enable DSH Blender Bridge（扩展会重新拨入 Gateway）→ `attach` |
| `addon_unresponsive` | 实例还列着但 ping 超时（进程僵死/面板崩了） | 同上；必要时关掉那个 Blender 重开 |

`status` 里多了 `live:{instanceReady, readyInstances}`：`instanceReady=false` 就是"记录在、Blender 不在"。
窗口被重置（`wm.read_factory_settings` / `read_homefile`）会把 addon 一起卸掉，会话**不会自愈** —— 只能人工重新 Enable 扩展（重新拨入 Gateway）。
`blender_py` 因此默认拦截这类脚本（`factory_reset_blocked`）；真要重置请改走 `blender_run(kind="headless")` / `action="worker"`，或显式传 `allow_factory_reset=true`。

**virtual-gui 的同意（3.3.1：在对话里点一下）**：

```text
# 1) agent 调 start —— 回执回来的同时，会话视图右侧栏「Blender 会话」tab 里出现卡片
#    （入口：会话头部按钮，有 pending 时带徽标数；输入框上方只有一行「Blender · N 待批准」）
blender_session(action="start", kind="virtual-gui")
#    （manual 策略下这次调用最多等 20 s）

# 2) 人点卡片上的「批准」/「拒绝」—— 不需要复制 id、不需要开终端

# 3) 同一次 start 立刻成功
#    → ok · consent_source=approved_request · state 由 pending 变 consumed
```

面板里能看到的（都与会话 API 同源）：待批准卡片（请求方 agent/session/role、动作、资源影响「当前实例数 / 上限 / 低内存降到 2」、有效期倒计时、批准/拒绝），认领表（instance id、owner 会话、`is_mine`、viewer、borrowed、heartbeat 年龄、归属剩余有效期、当前 grant），以及当前策略与来源。
面板只读 + 两个动作：它不会自己 spawn 进程，批准只释放 agent 自己刚发的那次 `start`。

**运维区（3.5 起，面板下半部分）**：不用开终端也不用问 agent，面板里直接看"这台机器现在在干什么"——

| 区块 | 看什么 | 数据源（只读） |
|---|---|---|
| 连接 / 通道 | 后端地址与来源、Gateway pid / uptime / RSS、插件版本与 provenance、通道"最近 ok 多久前 + 在飞 + 最后命令"、AI 是否暂停、写租约（holder / 剩余 / scope）、是否在渲染 | `GET /host/state` · `GET /health` |
| 作业 | `运行中 N ｜ 共 M` + 最近 6 条（短 id / kind / 状态 / 耗时），每行「日志」看 stdout+stderr 尾部 | `GET /host/jobs` · `GET /host/jobs/log` |
| 诊断 | 点「运行诊断」才取：verdict、插件版本、addon 就绪实例、Blender 版本/exe、缺口与修法、`next_actions`、配置摘要（HTTP / Gateway / 工作目录 / Blender exe / 配置文件 / 租约 TTL） | `GET /status` · `GET /doctor` |
| 设置（本机） | 后端地址覆盖（只写 localStorage，空=清除）、轮询间隔、原始快照 JSON | 浏览器 localStorage |

轮询是共享的一条：空闲 2500 ms、有作业或渲染时 1000 ms（设置里可改 800–15000 ms）；**单个请求失败只影响自己那一块**，其余照常显示。
诊断不会 spawn 任何进程；设置区只写浏览器本地的两个键（`dsh-blender-plugin:backend` / `…:panel:ops-poll-ms`），不改 owner / grant / 策略文件。
认领表每行还有「复制 attach」，复制出来就是 `blender_session action=attach instance_id=…`。

等满还没点：回执是 `state=pending`（带 `request_id`），批准后再 `start` 一次即消费；`wait_ms` 可按次调整（0 = 立刻返回）。

**策略 auto / manual / deny**（任选一处，改完 ≤250 ms 生效，不必重启）：

```jsonc
// ① 配置文件 dsh-blender.config.json（或 DSH_BLENDER_CONFIG 指向的文件）
{ "virtualGuiConsent": "manual" }        // default | auto | deny
```

```powershell
# ② 环境变量（优先级最高）
$env:DSH_BLENDER_VIRTUAL_GUI_CONSENT = 'auto'
# ③ profile 的插件配置键 virtualGuiConsent=auto —— 宿主拉起 Gateway 时注入成上面那个变量
```

面板里可以直接切三态（manual / auto / deny）：点 auto 需要二次确认；env `DSH_BLENDER_VIRTUAL_GUI_CONSENT` 存在时控件禁用并提示「被环境变量锁定」，POST `consent_policy_set` 回 409 `policy_locked`。写的是 `virtualGuiConsent` 一个键，文件旁留 `.bak`。

| 策略 | 回执 / 面板 |
|---|---|
| `manual`（默认，旧名 `ask`） | 面板卡片 + 等待；`consent_source=approved_request` |
| `auto`（旧名 `allow`） | 不弹卡片，`consent_source=policy:allow`；**面板常显「自动批准已开」** |
| `deny` | `reason=policy_denied`，不 spawn；面板显示 deny |

请求会落盘到 `<workDir>/consent/<request_id>.json`（Gateway 热更换代后从磁盘恢复，面板不丢状态），回执里也带 `request_id` 与 `human_action.approve/deny` 两条终端命令（等价通道）。

`action="reload"` —— **热更不重启**（改完 `lib/` 用它，不必重开 DSH）：

| mode | 它做了什么 | 回执要点 |
|---|---|---|
| `noop` | 宿主层与运行时层都已是磁盘版本（**宿主层必须可判**：清单属于本安装且判为 current） | 不动 pid、不写 profile |
| `hmr` | 宿主层变了（`lib/tools/**`、`lib/host/**`、`lib/constants.js`…）**或宿主层判不了** → 写 profile 的 `cordis.patch.yml` 触发 HMR 重组合，Gateway 随之换 pid | `pending=true` + `pidAfter=null` 是**正常**语义；用 `/health` 的 `backend.pid` 复核 |
| `gateway-restart` | 只有运行时层变了（`lib/runtime/**`）→ 重拉 Gateway 子进程 | `pidAfter` 是真实新 pid，`verdict` 复核后应转 `current` |

> **判不了 ≠ 已是最新**：宿主层清单缺失/读不到/来自**另一处安装**（共享目录里的仓库副本、另一个 profile）
> 时，回执的 `layers.hostKnown=false`，mode 按 `hmr` 走 —— 只有宿主重组合能重新写清单并自证。
> 旧行为在这里回 `noop`，于是「镜像做完、触发没做」被中断一次之后，两层都自证 current，
> 新的 `src/` 代码永远装不上（2026-11-19 现场）。
> 真陷在这个状态里：`blender_session(action="reload", force=true)`（或 `hot_update.ps1 -Force`）
> 不看判据强制重组合一次。

⚠ reload 的两个副作用（都按「**取消**」处理，不要当成续跑）：

1. **在跑作业会被取消**：headless / job 一律置 `canceled`。回执的 `jobsDropped` 列出被取消的 id，`note` 里点名"重跑请重新 submit"；长作业请避开热更窗口（或等 resume 能力）。
2. **同一段脚本里别接着调 `blender_*`**：`mode=hmr` 会把插件整代换掉、工具表随之刷新，正在执行的那段程序里后面再调 `blender_session(...)` / `blender_py(...)` 会绑定消失（报未知工具）。把 reload 单独作为一次调用，下一轮再接着干 —— 会话与场景不受影响。

```text
blender_session(action="reload")                  # 应用：该重组合就重组合，该换 Gateway 就换
blender_session(action="reload", dry_run=true)    # 只诊断：看 mode / changedCount / needsRestart
blender_session(action="reload", force=true)      # 不信判据，强制重组合一次（中断态/假 noop 的恢复）
```

#### `action="plan"` —— catalog 算子（38 family / 270 op）

> 不确定用哪个先 `op="catalog"`；单族 `args={"family":"audit"}`；算子细节 `<family>_help`；参数长尾可 `op="catalog", args={"tool":"blender_run"}`。
> **会话要求**：`catalog`、只读 op（如 `audit_scene / audit_mesh / plan_status / ledger / check_* / motion_joints` 等，`READ_ONLY` 集合）、`args.dry_run=true` 走本地或 Gateway 只读路径，**不要求 GUI 会话**；其余执行型 op 需要 ready 的 GUI 会话。

> **并发/无头强制**：白名单 op（`audit_mesh` / `img_*` / `visualreport_report` / `qc_render_views` / `montage`）+ `args.file` 时，`headless=true` 会在**有 GUI 会话时也**提交 fresh headless 作业（不抢 GUI），回执 `verdict=degraded` + `job_id`，用 `blender_run(action="wait")` 取件。
> 回执是 verdict-first 的单行 receipt（verdict / top_defects / next），可用 `attach_images=true` 附 ≤2 张产物图。

##### 多视角渲染 harness —— 一条命令出 N 张 + jsonl + 预算判定

```text
blender_op(op="qc_render_views", args={
  views: ["iso","front","right"],        # 具名视角 / "az=35,el=20" / {name, from, look_at, lens, ortho}
  res: [512,512], samples: 64,           # 采样同时写 EEVEE taa_render_samples 与 Cycles samples
  budget_s: 120,                         # 别名 thr；累计渲染超了立即停，已出的图保留
  outdir: "D:/DSH/blender/out/qc_render_p21",
  ref_path: "D:/work/ref_front.png", ref_box: [9,38,444,545]   # 可选：逐张走 qc_compare（默认固定对齐）
})
```

- **自动取景**：合并所有可见 mesh 的 AABB（`targets:[名字]` 可限定）→ 逐角解算相机距离 + `margin`（默认 1.12）；
  给了 `from` / `look_at` 就按显式机位，不再自动取景。
- **固定三点光**：SUN key 3.2 / fill 1.0 / rim 2.4，角度固定且相对相机方位角（+35°/45°、-50°/8°、+165°/30°）；
  **只在本进程内临时建**，出图后删除并把 scene 渲染设置全部还原（`lights_mode:"only"` 可临时屏蔽场景里的灯，也会还原）。
- **产出**：`<outdir>/<tag>_<view>.png` + `<outdir>/render_views.jsonl`，每行 = 一张图
  （`{view, ms, bytes, hash, path, res, engine, samples, camera, frame{bbox, margin_px, coverage, pred_bbox_px, proj_err_px}}`）。
- **预算**：`within_budget=false` + `stopped_early` + `skipped_views`；已完成的行 / 图**不删**。
- **长活**：本 op 在 GUI 会话里同步跑；预计 >5 min 或批量请提交后台作业 ——
  `blender_run(action="submit", kind="headless", preload="qc,qc_render", script="print('HEADLESS ' + K.dsh_qc_render_api['render_views']({...}))")`，
  或纯渲染走 `blender_run(action="submit", kind="render", …)`；之后 `wait` / `collect` 取结果。
- **不改场景**：GUI 进程里默认拒绝打开别的 `.blend`（要开就传 `allow_open_file=true`）；临时相机 / 灯用完即删。
- 自检：`blender_op(op="qc_render_help")` 出参数速查；`K.dsh_qc_render_api["selftest"]()` 跑取景 / 投影自检。

实测（350 可见 mesh / 512×512 / 64 采样 / EEVEE+RT）：3 视角 2124 / 798 / 565 ms、共 3487 ms、jsonl 3 行、
512 画幅四边余量 36 px（预测 bbox 与实出 alpha bbox 差 ≤2 px）；预算 1.0 s 的对照跑只出 1 张即停且图保留。

#### `action="loop"` —— 内环搜索（最核心的一个）

```text
blender_op(action="loop", op="start", spec={
  "setup":  "import random\nK.ob = bpy.data.objects['Cube']",
  "step":   "px = ns['i'] % 7; ns['params'] = {'sx': 1 + px * 0.1}",
  "measure":"ns['score'] = abs(bpy.data.objects['Cube'].dimensions.x - 2.0)",
  "iterations": 3000, "budget_ms": 20000, "interval": 0, "measure_every": 5,
  "minimize": True, "top_k": 20, "group_key": None
})
blender_op(action="loop", op="status", history=12)
blender_op(action="loop", op="board", limit=10)
blender_op(action="loop", op="export", path="/tmp/best_fit.py", top=3)
blender_op(action="loop", op="stop")            # 急停
blender_op(action="loop", op="bench", iterations=5000)
```

- `setup/step/measure` 源码共享命名空间 `ns`；`measure` 必须写 `ns["score"]`，可写 `ns["params"] / ns["metrics"] / ns["violations"]`；
- 预置：`bpy / K / math / random / numpy(np) / i / frac / penalize / anneal / record`；
- **必须给 `iterations` 或 `budget_ms`**（安全阀）；`interval=0` 最快；`redraw_every=0` 不重绘最快；
- 多目标：`ns['score'] = penalize(errors_dict, violations, weights, lam)`；步长退火：`anneal(v0, v1, ns['frac'])`；
- `top_k + group_key` = 候选表（跨对象批量时按对象分组各留最优）；
- 内环默认跑在 **GUI 会话**里（`target="gui"`，默认）；工具还保留一个内部无头实现（`target="session"`），**不是用户面能力**，需要无头请用 `blender_run` 提交作业；
- `op=help` 打印完整契约。

#### `action="opt"` —— 对象精简

```text
blender_op(action="opt", op="analyze")
blender_op(action="opt", op="join", args={dry_run:true})                      # 先空跑看报告
blender_op(action="opt", op="join", args={dry_run:false, save_before:"/tmp/pre_join.blend"})
```

合并规则（安全）：同集合 / 同材质 / 同父级 / 无修改器 / 无动画 / 无形态键 / 无自定义属性 / 无实例 / 非库链接 → **几何零损失**（面数顶点数不变）。务必先给 `save_before`。

#### `action="preset"` —— 配方库

把「参数组合」变成可保存、可套用、可分发的资产（与领域无关：材质 / 对象 / 场景 / 自定义 JSON）。

```text
blender_op(action="preset", op="save", name="硬表面金属", kind="material", tags="metal,hard",
           data='{"inputs.Metallic": 1.0, "inputs.Roughness": 0.25}')
blender_op(action="preset", op="list")                                  # 清单（可按 kind/tag 过滤）
blender_op(action="preset", op="get", name="硬表面金属")
blender_op(action="preset", op="apply", name="硬表面金属", targets="MAT:钢_外壳,MAT:螺栓")   # 实际写入
blender_op(action="preset", op="apply", name="硬表面金属")              # 不给 targets → 只预览（dry_run）
blender_op(action="preset", op="delete", name="旧配方")
blender_op(action="preset", op="export", names="硬表面金属,玻璃")       # 单个 bundle 便于分享给别的机器
blender_op(action="preset", op="import", path="D:/DSH/blender/tmp/presets/presets_bundle_x.json")
```

要点：data 用**点路径**；`targets` 支持 `MAT:名` / `OBJ:名` / `SCENE`；回执给 `applied / skipped / errors`（路径不存在只报错不静默）；`overwrite` 默认 true。
实测：存 `{"render.resolution_x":640}` → `apply targets="SCENE"` → 场景分辨率 720 → **640** 真实生效；dry_run 预览不写盘。

### ③ `blender_py` —— GUI Python（改一步看一眼）

| 参数 | 说明 |
|---|---|
| `code` / `file` | 要执行的 Python 源码 / 磁盘上的 `.py`（二选一；`file` 自动注入 `__file__` + sys.path） |
| `see` | 跑完是否抓当前视口一帧（默认 true） |
| `max_size` | `see` 的最长边像素，默认 560 |
| `force` | `see`：同画面默认不重复附图，`true` 强制重发 |
| `wait_ms` | 等其它 agent 的 py 跑完的毫秒数（0–5000，默认 0）；**>0 时真的排队等锁**，等满仍被占用才回 `py_busy`（带 `retryAfterMs` 与 holder） |
| `checkpoint` | `auto`（默认，执行前打一次文件级快照，label=`py-<uuid8>`）或 `off`；scoped grant（非 exclusive）**不发起快照请求**，回执写 `checkpoint=none` + 原因（要回退用对象级 txn mark/revert） |
| `write_scope` | 写作用域：`exclusive`（默认）/ `collection:名` / `prefix:名` / `object:uid`；子 agent 必须与父 grant 覆盖范围一致 |

- 只在 **ready 的 GUI 会话**里执行，固定 `exclusive`（不排队列）；**没有会话直接拒绝**，不会启动 headless、不会自动降级。
- 代码在 **Blender 主线程**执行，预置 `bpy / math / mathutils / Vector`；每次调用是全新命名空间，跨调用状态挂**持久内核 `K`**。
- `see=true`（默认）会顺带回一帧，GUI 整步 ≈105 ms；超过 ~1 s 的重活请改用 `blender_run(kind="headless")`。回执里的 `SEE` 行会注明**这是共享视口**（用户正在看的 3D 视图，不是调用方机位）；同画面去重按调用方分键，别的 agent 看过的画面不会让本次静默少一张图。
- **回执自证**：每次带 `changed / faces_delta / verts_delta / objects_delta / changed_objects / edit_mode / warnings`。
- **跨调用指纹（C-6）**：回执带 `scene_fingerprint:{before,after}`；宿主按会话记住上一次收工时的指纹，下次调用若 `before` 与它不同，会加一行「⚠ 场景自上次调用后已变（sig a→b）」并给 `scene_drift` —— 多人共机时 `before/after` 只在本调用窗口成立。
- **变更归属（C-7）**：`changed_objects_mine` / `changed_objects_other` 按本次 `write_scope` 分桶（owner / 未声明 scope 时全算 mine）。坐标签名改成**每对象固定预算**，不会再因为增删一个对象把后面一批对象误报成 changed。
- **产物（C-16）**：`file_ops` 为真时回执另给 `artifacts[]`（`.blend` 与 `Render Result` 的真实路径/字节数），文本带「产物：…」一行；场景不变与产物分开陈述。
- **动画域（C-14）**：状态签名纳入 action / slot / fcurve 数与关键帧，只改动画也会 `changed=true`；`world_snapshot` 与 `anim_rig_report` 的 action 行补 `fcurve_count`。`CANCELLED` 或几何/UV 写算子 `FINISHED` 但没改动 → `ok:false`（`op_cancelled` / `op_no_effect`）；`bake / export / bind / 选择` 这类不写场景的 ops → `ok:true` + `no_scene_change` 警告，不会让 agent 误重试。
- **越界写**：grant 外的改动回 `scope_violation`。**新建**的越界对象会被插件删除（`rolled_back`），它独占的 mesh datablock 也一并清掉（`purged_meshes`；材质同理 `purged_materials`）；**已存在**对象被改则列在 `unrolled`、`rollback_complete:false`，回执给清理指令（txn restore / 手工）。若仍有零引用数据，用 `blender_op(op="audit_purge_orphans")` 收尾。
- **`no_scene_change` 语义**：它表示**最终**场景内容没有变化（`changed=false`），与是否调用 ops 无关 —— 纯 `print` 也会是 `true`；是否“调过 ops”看 `has_ops`。**产物型执行**（`render.render` / `wm.save_mainfile` / `export_*`）另给 `file_ops=true`，回执改说"场景不变是预期、产物看脚本里的 filepath"，不再推 `no_scene_change` 警告。域外新建被回滚后若最终一致也是 `true`；越界判定以 `scope_violations / rolled_back / rollback_complete` 为准，不要拿 `no_scene_change` 当失败判据。
- **结果未知口径**：客户端 180 s 到点或连接中断时回 `code=outcome_unknown`，**不代表脚本失败**——它可能还在 Blender 里跑。回执带 `request_id` 与 `checkpoint`，下一步是 `blender_inspect command=get_scene_info` 看有没有重复材质/节点，或 `blender_session(action="txn", op="restore", label=<checkpoint>)` 退回执行前；确认场景没变才重跑。快照建不成（lease 写通道/大场景）时降级为 `checkpoint=none` + 警告，脚本照跑。

```text
blender_py(code="K.n = getattr(K, 'n', 0) + 1\nbpy.data.objects['Cube'].rotation_euler.z += 0.4", see=True)
blender_py(file="//tools/probe.py", see=False)     # 直接跑工作区脚本（K.run 语义，会回收 stdout）
```

### ④ `blender_see` —— 看 GUI（唯一截图入口）

| 参数 | 说明 |
|---|---|
| `viewpoint` | viewport（默认，当前 GUI 视口）/ camera（当前帧相机）/ custom（from+look_at 自定义机位） |
| `mode` | frame（默认，单帧）/ sequence（固定机位序列帧，只 viewport / custom） |
| `camera` | viewpoint=camera 时可选相机名；省略或 `true` = `scene.camera`；其他 viewpoint 不接受 |
| `aspect` | 1:1 / 4:3 / 16:9（默认 16:9）；viewport / custom / sequence 用；camera 也接受（按该比例重算分辨率，不改相机） |
| `max_size` | 固定档位：1:1 544/768/1024/1280；4:3 640/960/1280；16:9 1024/1152/1280；camera 544/768/1024/1280；默认 1024 |
| `from` / `look_at` | 【custom】相机位置 / 注视点，`"x,y,z"` 或数组 |
| `lens` / `ortho` / `ortho_scale` | 【custom】焦距 mm（默认 50）/ 正交开关 / 正交尺度（贴长边，默认 10） |
| `fit` / `fit_object` | 【custom】自动取景：`object\|scene\|<对象名>`，按 bbox 一次框全（可省略 `from/look_at`）；默认正交、margin 1.15 |
| `clip_start` | 【custom/current/camera】近裁剪面 BU；近摄全白时调小（默认 0.1） |
| `full` + `area` | frame + viewport：`full=true` **省略 area = 整个窗口一张图**；给 area 才截该区域（固定 1024 长边，看 UI 时用） |
| `shading` / `overlays` | 【custom / sequence】临时切换着色（WIREFRAME/SOLID/MATERIAL/RENDERED）/ 覆盖物，出图后还原 |
| `diagnostics` | 【frame + custom】强制跑覆盖率 / 空帧诊断（默认按需） |
| `seconds` / `fps` | 【sequence】采样时长 0.2–20 秒（默认 2）/ 采样频率 0.5–8（默认 4）；帧数 `round(seconds*fps) ≤32` |
| `force` | 同画面默认不重复附图；`true` 强制重发 |

**固定档位**（只给 `aspect` 时取该比例最小档；非法值直接报错，不夹取）：

| aspect | 可选 max_size |
|---|---|
| 1:1 | 544 / 768 / 1024 / 1280 |
| 4:3 | 640 / 960 / 1280 |
| 16:9（默认） | 1024 / 1152 / 1280 |
| camera | 544 / 768 / 1024 / 1280 |

`aspect` 与 `max_size` 是**硬配对**：`aspect="16:9"` + `max_size=768` 直接 `invalid_params`（768 只属于 1:1 / camera），不夹取。`from` / `look_at` 收字符串 `"7,-7,5"` / `"7, -7, 5"` 或数组 `[7,-7,5]`；解析不了回 `invalid_params` 并**回显原值**（不是 502）。

```text
blender_see(max_size=560)                                       # 当前视口帧
blender_see(viewpoint="custom", from="9,-9,6", look_at="0,0,1", lens=35)
blender_see(viewpoint="custom", from="0,0,12", look_at="0,0,1", ortho=True, ortho_scale=12,
            shading="MATERIAL", aspect="1:1", max_size=1024)
blender_see(viewpoint="camera", camera="Cam_hero")              # 当前帧求值相机（渲染比例）
blender_see(viewpoint="viewport", full=True)                    # 整个 Blender 窗口（省略 area）
blender_see(viewpoint="custom", fit="object", aspect="1:1")      # 按选中对象 bbox 一次框全
blender_see(viewpoint="custom", from="9,-9,6", look_at="0,0,1",
            mode="sequence", seconds=2, fps=4)                  # ≤32 帧 + 逐帧 hash
```

- **只服务 GUI 会话**：没有 ready 会话直接拒绝；**不会**回落无头、也不会启动 Blender。
- `viewpoint="camera"` 只取当前帧求值，**不改** `scene.camera` / 帧 / 选择 / 用户视口；PANO 不支持，DOF / 运动模糊只给 `preview_only`。
- `mode="sequence"` 不执行 code、不改场景；要"先跑一段代码再逐帧看"用 `blender_py` 执行代码 + 再 `blender_see`；逐帧 hash 全相同 = 画面没变（动画没跑起来 / 参数没生效）。`fps` 别开太高（每帧占主线程 ~55–100 ms，会卡人）。
- `full=true` 整窗截图必须 GUI；`view_size` 已移除 —— 画幅用 `aspect` + `max_size` 固定档位表达。
- **标定**：回执每次带 `px_per_mm` / `visible_threshold_mm`（4.5 px 经验阈值）/ `frame_width_mm` / `coverage_estimate`。可见阈值折算：全身 1.66 m @1024 ≈ 8 mm；200 mm 零件 ≈ 0.9 mm；100 mm 零件 ≈ 0.45 mm。
- **近摄全白**：`coverage=0` 且距离 < `clip_start` 时回执是 `frame_clipped_by_near_plane`（带 `suggest_clip_start`），不是 `frame_looks_empty`；把 `clip_start` 调到 0.001–0.01 再取一次。
- 相机动画 / 批量渲染走 `blender_run(action="submit", kind="render", …)`，不要用截图代替渲染。

### ⑤ `blender_run` —— 作业 / 渲染 / 调参（唯一作业入口）

| action | 作用 | 要点 |
|---|---|---|
| `submit` | 提交作业：`kind="render"`（声明式渲染）或 `kind="headless"`（跑脚本） | **立即返回结构化句柄**：顶层 `jobId/state/slot/queued_ahead` + `envelope{contract:"receipt.v2", job_id, …}`；不用再正则文本；没有同步模式 |
| `status` | 单次查状态 | `state` / slot / timing / pid / result / artifacts |
| `wait` | 阻塞到终态或超时 | 默认 **120 s**、上限 **600 s**；**超时不取消作业** |
| `collect` | 取日志与产物 | `stdout` / `stderr` 尾部（`tail` 默认 4000）+ result（exit / signal / parsed）+ artifacts |
| `cancel` | 取消作业 | 幂等：已到终态也回 ok；清进程树 |
| `list` | 列作业 | **默认只列本会话**（`owner=me`）、默认 20 条：`limit`（0=不分页）/ `offset` / `since_ms` 翻页，`owner=all` 看全部会话；回执给 `jobs[]` / `count` / `total` / `offset`，文本超过 20 行只列前 20 行并提示剩余条数 —— **这是唯一能枚举 Blender 队列的入口**（DSH 宿主的 `job_list` 只列宿主后台作业） |
| `perf` | 队列指标 | pending / byState / slots（gpu·cpu）/ oldestQueuedAt |
| `tune` | Cycles 渲染分析 | `op="status"` / `"analyze"` / `"apply"` / `"revert"` / `"help"` |
| `help` | 契约 | |

| 参数 | 说明 |
|---|---|
| `action` | submit / status / wait / collect / cancel / list / perf / tune / **worker** / help（默认：带 `kind` 则 submit，否则 list） |
| `kind` | submit：`render`（声明式渲染）或 `headless`（跑脚本） |
| `id` | status / wait / collect / cancel 的 jobId |
| `priority` | submit：队列优先级（-100..100，默认 0；越大越优先） |
| `timeout_ms` | wait：等待上限（默认 120000，最大 600000，**超时不取消**）；headless：进程上限（默认 180000，最大 1800000） |
| `tail` | collect：日志尾部字符数，默认 4000 |
| `state` / `owner` | list：按状态过滤 / 会话过滤（`me` 默认 · `all` · 具体 session id） |
| `limit` / `offset` / `since_ms` | list：本页条数（默认 20，上限 200，0=不分页）/ 跳过条数 / 只列该时间戳之后的作业 |

`kind="render"`（声明式最终渲染，**不接受 script**）：

| 参数 | 说明 |
|---|---|
| `file` | 要渲染的 `.blend` |
| `output` | 输出文件模板（如 `//render/frame_####` 或绝对路径）；`//` 是 Blender 的"相对 .blend 目录"语义，工具会解析成绝对路径；**没有 `file` 时 `//` 在参数校验阶段就被拒**（不再 mkdir `C:\`） |
| `outdir` | 输出目录 |
| `frames` | 帧区间 `[start,end]` / `"1-10"` / 单帧 `5`；**给了区间自动加 `-a`（相机动画）** |
| `resolution` | `[width,height]` |
| `samples` | 采样数（Cycles samples / EEVEE `taa_render_samples`）；按**实际 engine**落地，`applied.samples` 回读 |
| `engine` | `CYCLES` / `BLENDER_EEVEE_NEXT` / `BLENDER_WORKBENCH` |
| `device` | `auto`（默认，能绑 GPU 就绑）/ `gpu` / `cpu`；只对 CYCLES 有意义 |
| `compute_device_type` | `OPTIX` / `CUDA` / `HIP` / `ONEAPI` / `METAL` / `NONE`；不传时按 OPTIX→CUDA→HIP→ONEAPI→METAL 试 |
| `format` | 图片格式（PNG/JPEG/OPEN_EXR…） |
| `camera` | `true` 用场景相机，或相机对象名 |
| `channels` | 渲染通道数组：`render` / `alpha` / `mask` / `ink`（默认 `["render"]`）。每通道回路径 + `foreground_px` / `coverage` / `n_components` / `bbox`；缺 ink 对象时该通道 `skipped`、整体 `verdict=degraded`（degraded ≠ 通过，但不是失败） |

> **headless 的设备前导（3.5，C-9）**：每个 `kind="headless"` 作业都会在脚本前跑一次设备枚举（默认 `device=auto`），结果同样写进 `result.parsed.applied`（`devices_used / compute_device_type / scene_device / fell_back_to_cpu / warnings`）。以前 headless 不做这件事：`--factory-startup` 下 `compute_device_type=NONE`，脚本自己切 Cycles 也只绑 CPU（1080×1920/64spp 实测 42.7–45.5 s/帧 vs 12.2–14.8 s/帧）。
>
> **render 的设备回执（2026-11-20 第二阶段 P1）**：CYCLES 渲染会先按 `device` / `compute_device_type` 绑定设备，并把实际结果写进 `result.parsed.applied`：`engine / samples / scene_device / compute_device_type / devices_used / fell_back_to_cpu / warnings`。默认 `device=auto` 会尝试 GPU；绑不上就回落 CPU，同时给 `warning gpu_unavailable / gpu_not_bound`，**不再静默**。注意 CPU 渲染日志里的 `Copying BVH to device` / `Copying Mesh to device` 指的是内存，不是显卡 —— 判后端请看 `applied`。

`kind="headless"`（fresh `blender -b` 进程跑脚本）：

| 参数 | 说明 |
|---|---|
| `script` / `script_file` | Python 源码 / 直接跑一个 .py 文件（后者自动注入 `__file__` + sys.path，多文件工程更省事） |
| `file` | 打开的 .blend（WSL 或 Windows 路径都行，自动映射） |
| `outdir` / `out_json` | 产物目录 / 结构化结果落盘路径（都接受 WSL 路径） |
| `timeout_ms` | 进程上限：默认 180000，上限 1800000（到点杀进程树） |
| `preload` | 预载 runtime 模块（逗号分隔）→ `K.dsh_*_api`，如 `"audit,qc,qc_render"`、`"assembly,audit,contract,clearance,gate,mesh_fix,geo,txn"`、`"imgtools"`。名不存在时作业在**准备阶段**就失败（`job_prepare_failed` + 可用模块清单），不会跑到一半才 NameError |
| `engine` | `cycles`（先切 CYCLES，再按设备前导绑 GPU）/ `eevee`（保留 EEVEE 默认，设备前导只报道具）/ `keep` / `none` |
| `device` | `auto`（默认，能绑 GPU 就绑）/ `gpu` / `cpu`；headless 也会初始化 Cycles 设备并回读 |
| `compute_device_type` | `OPTIX` / `CUDA` / `HIP` / `ONEAPI` / `METAL` / `NONE`；不传按 OPTIX→CUDA→HIP→ONEAPI→METAL 试 |
| `factory_startup` | 默认 true（干净、快、不与运行中的 GUI 会话抢资源）；要用用户偏好 / 启动文件设 false |
| `bootstrap` | 默认 true（注入持久内核 `K` + 默认模块 kit/geo/audit，与 GUI 同一份 `KERNEL_BOOTSTRAP`）；false 时脚本原样跑 |
| `workdir` / `env` / `args` | 脚本内 chdir + sys.path 首位 / 子进程环境变量 / 额外命令行参数。**相对路径（`script_file` / `file`）按 workdir → 工作区 env → Gateway cwd 解析，并在提交前校验存在性**（缺文件直接 `input_missing`，不会起进程）。`args` 收 **string（按空白/引号分词：`--flag "a b"`）或 string[]**，两条路都进 `sys.argv` 的 `--` 之后；**调用方的 args 占第 0..n-1 位，注入的 outdir 固定在最后一位**（C-10，旧顺序会把目录名顶到第 0 位）；`env` 真进子进程 |
| `shots` | 多视角一体化出图（走 `qc_render_views` harness，见 `7.2） |
| `expect` | 断言（如 `{"minNewObjects":1}`）：空跑即失败 |
| `include_noise` | 产物清单是否含 `__pycache__` / `*.blend1`（默认过滤） |
| `hard_exit` | 完成后直接退出（默认 true，规避 Blender 5.2.3 退出 AV；false = 旧行为） |
| `gpu` / `run_id` | GPU 前导语义（auto / true / false）/ 显式作业 id（台账复现） |

约定：脚本里 `print("HEADLESS {json}")`（单行 JSON）→ 工具把最后一行解析成 `result.parsed`；大结果给 `out_json`。

**相对路径与"先起进程再报错"（3.2）**：`script_file` / `file` 给相对路径时，工具层先从**调用方的会话工作区**取根（workingDirectory 服务 → Session 的 cwd → `DSH_BLENDER_WORKSPACE`/`DSH_WORKSPACE`/`DSH_PROJECT_DIR` → 宿主进程 cwd），按 `workdir → 会话工作区 → 工作区 env → Gateway cwd` 绝对化并校验；后端再用同一套档位（工具层把会话工作区作为 `workspace` 一并传下去）兜底解析。找不到就返回
`input_missing`（带 `evidence.tried` 的完整候选列表 + `evidence.bases` 的来源分层），**一个 Blender 进程都不会起**。
提交成功的回执会多一行 `path_base: …`：命中会话工作区时写明来源；**只落到宿主进程 cwd 时明确写"回落"**（那通常是 DSH profile 目录，不是你的工作区）——这时给绝对路径或显式传 `workdir=<工作区根>`。

`action="worker"` —— **持久无头内核**（改一步看一眼，不再每次冷启动）：

| op | 作用 | 要点 |
|---|---|---|
| `digest` | 场景**内容哈希**基线（`digest_scope=scene`） | 不改场景、不落盘；回 `digest / digest_scope / kit_source / auto_restore=false` |
| `exec` | 在同一常驻 `blender -b` 里跑 Python | `digest=true` 时前后各算一次内容哈希（见下）；`code` 必填；`file` 只在启动时打开（已启动且文件不同回 `worker_file_mismatch`，不静默换场景）；`script` 是 headless 参数，传进来会直接被拒；`print("HEADLESS {json}")` 仍是结构化回执；`purge` 热重载模块前缀 |
| `see` / `watch` | 同进程离屏取帧（Workbench，稳态 ~30 ms） | `spec={width,height,from,look_at,lens,ortho,shading}`；`watch` 可先跑 `code` 再看帧序列 |
| `checkpoint` / `revert` / `checkpoints` / `relocate` | **文件级 checkpoint 栈** | `label` 命名；回执给 `checkpoint.path`；`revert label="last"` 回上一档；**revert 后 `file` 仍是原工作文件**（先给原文件留 `pre_revert_*` 备份，再写回；回不去时显式 `file_changed=true` + `relocate`） |
| `reset` | 清场景（保留 `K` 与 preload 模块） | 批量白模之间用 |
| `status` / `list` / `start` / `stop` / `restart` | 热进程管理 | `restart` 换干净进程（脚本脏了用它）。回执按**终态**判定：`start` 等进程到 ready 才回，回执写 `alive/ready/pid/port`（还没 ready 时写 `pending` + `next_action=status`，**不是失败**）；`stop` 等进程真的退出才回，写 `stopped/alive` 与 `cleared:{pid,ready}`（停干净后快照里的 `pid` 一定是 `null`，不会再出现 `alive:false` + 旧 pid 的读法），本来就没在跑时写"不是失败、不用重试"。同一个 name 的并发/重试 `start` 会加入同一次启动（回执带 `joined`），不会起第二个进程抢端口 |
| `session` | 热进程名（默认 `default`） | 多个场景并行时各用一个名字，互不干扰 |
| `help` | 参数表 + checkpoint/revert 语义 + see/watch 的 spec 字段 | 不依赖后端，直接返回 |

```text
blender_run(action="worker", op="exec", code="import bpy; bpy.ops.import_scene.gltf(filepath=r'D:\a.glb')")
blender_run(action="worker", op="checkpoint", label="s1_raw")     # → checkpoint.path=…\01_s1_raw.blend
blender_run(action="worker", op="see", spec={"width":640,"from":[7,-7,5],"look_at":[0,0,1]})
blender_run(action="worker", op="exec", code="…改鞋口…")
blender_run(action="worker", op="see")                            # 同一个进程，~30 ms 出图
blender_run(action="worker", op="revert", label="s1_raw")         # 一行回滚，不用手工另存；file 回原路径
blender_run(action="worker", op="relocate", file="D:/proj/work.blend")  # 显式换工作文件（写盘一次）
```

> worker 是独立无头进程（不影响 GUI 会话，也不受写租约阻塞）；串行执行，长代码会占住它 —— 超长任务仍走 `kind="headless"`。
> worker 端口**按 session 记账**：probe-p7=9879、default=9880…… 不是全局固定端口；`DSH_WORKER_PORT` 只是起始端口，同名的热进程会复用。
> checkpoint 目录默认 `<frame-dir>/dsh-checkpoints`，可用 `outdir` 指定；`<dir>/index.json` 记栈，跨进程重启仍在。
> 快照容量有上限：默认保留最近 20 档 / 1024 MB，超出自动删最老的（回执 `auto_pruned`）；`DSH_TXN_KEEP` / `DSH_TXN_MAX_MB` 可调，`txn op=prune` 可手动清。单档大场景仍可能 ~10 MB，长会话请定期 prune。

**digest 语义（工单 7）**：`op=digest` 取基线；`exec digest=true` 在执行前后各算一次场景内容哈希，信封 `evidence` 固定给
`digest_before / digest_after / changed / digest_scope[] / restore_applied / kit_source / elapsed_ms / auto_restore / worker:{session,file}`，并显式 `auto_restore=false`。`digest_scope` 是**数组**（实际参与哈希的域：objects / mesh / materials / actions）；`worker.file=null` 表示 factory startup。
`changed` 只看内容哈希（`digest_before !== digest_after`），**不看 mtime**；改了**不会自动回滚** —— 要回退用 `checkpoint/revert`。
`filepath` **不进哈希**：同内容 `save_as` 换路径回 `changed=false` + `filepath_changed=true`；对象变换（含 `matrix_basis`）、材质（Roughness/Metallic/Base Color…）与修改器参数都进哈希，`faces_delta` / `verts_delta` / `objects_delta` 直接给数字。
`kit_source`：`boot` / `boot-degraded` / `bootstrap`。哈希覆盖**场景内**对象名/类型/变换（`matrix_world` + `matrix_basis`）/材质槽/修改器参数、被引用材质的 Principled 参数、网格拓扑与顶点坐标 + UV（上限 20 万顶点，超了 `digest_truncated=true`，仍按拓扑+尺寸哈希）。`bpy.data.*` 里的孤儿/默认材质（如 `Dots Stroke`）不算，保证 save→reopen 后 digest 不变。
验证改名**别用 `bpy.data.objects[0]`**（集合按名排序，改名后索引会换人，看起来像回滚）：用「按名字存在性 + digest」双证。

**layered action / `K.action_fcurves`（工单 10）**：Blender 5.2+ 删了 `Action.fcurves`，统一走 `K.action_fcurves`（kit 实现；worker / GUI / blockout 同一份）。
老 GUI 会话的 `K` 缺 helper 时，下一次 `blender_py` 的 bootstrap 会**重载 kit** 并补上 `K.action_fcurves`；blockout 相机关键帧线性化不再 `except pass` 静默失败（失败会进 `warnings`）。
GUI 探针脚本：`tests/e2e/blender/p10c_gui_probe.py`（只建/删临时对象与临时相机，跑完对象数/名字集合必须回到基线；第二次跑 `reload_count=0` 验幂等）。
CI 矩阵跑 Blender **4.2.10（基准）与 5.3.0（preview）**：`extension` 与 `linux-preview-see` 两个 job 各自两腿，5.3 用独立缓存 key 与官方 sha256 字面校验；5.3 首跑若暴露 addon/Xvfb/EEVEE 漂移会真红（不静默降级、不加 continue-on-error）。

参数透传对账：作业回执的 `result.provenance` 固定给出 `{args, env, env_keys, preloads, bootstrap}` —— `args` 是分词后的 argv 尾、`env_keys` 是**真注入**的自定义环境变量键（`DSH_*` 另计）。`status/collect` 的 `provenance` 行直接可读，排查"参数没到脚本"时先看它。

**作业生命周期**（`submit` → 按 id 收结果）：

```text
blender_run(action="submit", kind="headless",
            script_file="D:\\work\\proj\\tools\\build.py", args="--part hull",
            env={"STAGE": "qc"}, outdir="D:\\work\\out", timeout_ms=1200000)
# → 回执：text 首行 RUN <jobId> · headless · queued …；同时顶层 jobId/state/slot/queued_ahead + envelope(job_id)
blender_run(action="status",  id="<jobId>")     # state / slot / timing / pid / result / artifacts
blender_run(action="wait",    id="<jobId>", timeout_ms=600000)   # 阻塞到终态或超时；超时不取消
blender_run(action="collect", id="<jobId>")     # 日志尾 + result（exit/signal/parsed）+ artifacts
blender_run(action="cancel",  id="<jobId>")     # 幂等，清进程树
blender_run(action="list", state="running")
blender_run(action="perf")
```

- **队列有界**：pending 64 / GPU 1 / CPU 2；满了返回 `QUEUE_FULL`（等 running 完成或 cancel 不需要的）。
- **枚举口径**：`blender_run(action="list")` 是 Blender 队列的唯一枚举；DSH 宿主的 `job_list` / `job_output` 只认**宿主后台作业**，看不到 submit 的 `jobId`（两者 id 空间不同，别拿 blender 的 id 去 `job_output`）。
- **没有同步模式、没有 `as_job` / `wait_s`**：提交即返回，长活永远走 submit → wait / collect。**客户端超时 ≠ 作业失败**，服务端子进程继续跑、产物仍落盘。
- **失败给结构化信息**：`logs`（全量日志路径）/ `lastException` / `traceback` / `reason`；`outdir` 产物默认过滤 `__pycache__ / *.pyc / *.blend1|2 / tmp*`。
- **GPU 前导**：headless 默认注入 GPU 前导（`gpu:"auto"`）并回传 `gpu` 字段 —— 无头进程读不到用户偏好，Cycles 会静默回落 CPU（实测 15.4×）。
- 脚本内可用 `dsh_stage("building")` 打阶段心跳（单行 `DSH_STAGE {json}`）；`status` 解析最后一条，长任务可观测。
- 脚本内可用 `K.win_path / K.wsl_path / K.blend_path / K.out_dir`；异常回传 partial stdout / traceback。

**render 通道（`channels`）**：`-a` 渲完之后自动跑一次 numpy 收尾（`runtime/py/render/channels_impl/metrics.py`），
把每通道路径与四项指标折进 `result.parsed` —— `status` / `collect` 回执直接可读（`channels  verdict=…` + 每个通道一行 + `repro` 命令）。

- `render`：`-a` 已经渲好的那一帧（底图）。
- `alpha` / `mask`：同一张透明背景单帧（`<outdir>/channels/transparent_####.png`）；`alpha` 按"任意不透明度"算覆盖率，`mask` 按 `alpha ≥ 0.5` 算实体掩膜（没有对象选择依据时就是场景可见对象的轮廓）。
- `ink`：需要名字带 `ink` / `outline` / `lineart` / `描边` / `墨线` 的对象；有就只渲这些对象 + Freestyle 线稿，**一个都没有时该通道 `skipped`（原因 `no_ink_object`）而整体判 `degraded`，不是失败**。
- 三态：请求的通道全部 `ok` 才 `pass`；有 `skipped`/`error` 是 `degraded`；只有 `render` 底图读不出来才是 `fail`。

```text
blender_run(action="tune", op="status")     # 现状（引擎/设备/采样/降噪/persistent/对象数）
blender_run(action="tune", op="analyze")    # 差分实测：每轮 CPU 侧同步 vs 每采样 GPU 成本（占主线程十几秒）
blender_run(action="tune", op="apply")      # 预设：persistent_data + 降噪器自动判定 + auto_tile off + 采样上限
blender_run(action="tune", op="revert")     # 还原 apply 之前（自动存快照）
```

经验值（作者机器，2318 对象）：**每轮 CPU 同步 ≈4.2 s，persistent_data 让重复渲染 14.6 s → 0.79 s**；砍采样对 CPU 侧几乎无帮助。

### ⑥ `blender_inspect` —— addon 只读命令目录与执行

- 不给 `command` = **help**：列出 addon 的可执行**只读**命令（`name(args)` / enabled / pause_safe / description / access / gate）。
- 内部传输命令（`execute_code` / `get_viewport_screenshot` / `send_selection_to_dsh` / `send_collection_to_dsh`）**不列出也不可执行**：执行 Python 用 `blender_py`，截图 / 看视口用 `blender_see`，作业用 `blender_run`。
- `bpy_api_lookup` 有**无头探针**（工单 11）：`force_headless=true` 时即使 GUI 在线也走无头；没有 addon 时自动回落。探针复用一个热 worker（session=`bpy-api-probe`），连发多次只起 1 个进程，结果按 query 缓存 5 分钟（`cache_age` 秒）。
  - evidence：`source=headless` / `blender_version` / `cache_age` / `hits[]` / `degraded` / `probe{blender_exe,elapsed_ms,reused,worker_pid}` / `drift{expected,actual,level,message}`。
  - 漂移：`expect_version` 与实测不一致 → `drift.level=warn`，message 同时含两个版本号；`version_fixture` **只作测试注入**（覆盖用于比较的实测版本，`version_source=fixture`），不进产品默认路径。
