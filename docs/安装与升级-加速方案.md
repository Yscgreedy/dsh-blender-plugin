# 安装与升级加速方案（2026-11-21 实测）

> 目标：把「把本 checkout 装/更新进 DSH」从**多步手工**变成**一条命令**，并且不再踩坏
> `runtime/ext`（Open3D / glTF-Validator 的可选工具链）。
> 适用：DSH desktop 的 profile 安装（`~/.dsh/profiles/<profile>`），Windows / macOS / Linux 同一套命令。

## TL;DR

| 场景 | 命令 | 耗时（本机实测） |
|---|---|---|
| 日常开发（一次切成 link，之后每次更新） | `npm run dsh:link` → 之后 `npm run dsh:reload` | 首次 ~10 s；之后 **~6 s** |
| 按发布包形态覆盖安装 | `npm run dsh:install` | **~9 s**（复制 0–3 个文件时 ~2 s） |
| 只验证（不装） | `npm run dsh:verify` | ~1 s |
| 顺带更新 Blender 扩展 | `npm run dsh:install -- --with-addon` | +0.2 s（免去 Install from Disk） |

三条命令都会：**只复制变化的文件**、**永不删除 `runtime/ext`**、**写 profile 触发 HMR**、
然后自证 `/health`、`/status`、`/plan catalog`（ops / families）。

## 现状：手工升级到底慢在哪（同一台机器实测）

| 步骤 | 命令 | 耗时 | 问题 |
|---|---|---|---|
| 1 | `npm run build` | 4.7 s | tsc 两遍；无 incremental（runtime 2.2 s + host 1.4 s） |
| 2 | `npm pack`（默认） | 7.3 s | `prepack` 又跑一次 build —— 编译做了两遍 |
| 3 | `tar -xzf` | 0.9 s | — |
| 4 | `robocopy /MIR` 覆盖安装目录 | 1.2 s | **镜像前 18,513 个文件 → 镜像后 1,338**：`runtime/ext` 被整目录删掉 |
| 5 | 恢复 `runtime/ext/venv` | **16.8 s** | 16,812 个文件；忘了恢复 → `ext.*` 能力静默消失 |
| 6 | `blender_session action=reload` + 等新 Gateway | 6–10 s | 正常语义（HMR 换 fiber / Gateway 换 pid） |
| 7 | 手工 attach + 逐项验证 | 1–2 min | 会话记录随 Gateway 清空；catalog/version 要人肉核对 |

合计 **~40–60 s**，且有两个不可见风险：ext 被删（能力消失但没人报错）、忘记 attach（工具看着"没会话"）。

## 对策（已实现：`scripts/install-dsh.mjs`）

| 瓶颈 | 做法 | 收益 |
|---|---|---|
| prepack 重复编译 | `npm pack --ignore-scripts --json --dry-run` 只拿**发布文件清单**，不产 tarball、不跑 prepack | −4.7 s |
| 镜像删除 ext | **merge-only**：按内容 sha256 只复制变化文件；只删除"上次 manifest 里有、这次没有"的文件；`runtime/ext`、`node_modules`、`__pycache__` 永不删 | −16.8 s，且不再有静默能力丢失 |
| 版本目录写死 | profile 依赖 `file:` 指向的目录通过 `node_modules/dsh-blender-plugin` 的 realpath 解析；`--mode link` 直接把依赖改成 `link:<repo>`（备份 package.json + pnpm install） | 版本升级/目录改名不再改脚本 |
| reload 与验证靠人 | 复用 `lib/host/reload/profile.js` 的 `triggerProfileHmr`（同一行注释、原子写）；轮询 `/health` 等 pid 换代；再读 `/status` 与 `POST /plan {op:"catalog"}` | 一步完成，失败有明确 `!` 行 |
| Blender 扩展手工装 | `--with-addon`：把 `extension/dsh_blender_bridge` 复制进 `<Blender>/<ver>/extensions/user_default/`（自动挑最高版本，可 `--blender-version`） | 省掉 Install from Disk；代码生效仍需 Reload Scripts/重启 Blender |

### 安全边界

- `--dry-run`：只算计划（清单来自 `npm pack --dry-run --json`），不复制、不 reload、不写 manifest。
- 删除范围**只限 manifest 记录过的发布文件**；第一次运行没有 manifest 时只复制、不删除。
- profile 侧只追加一行 YAML 注释（不碰结构；与 `blender_session action=reload` 完全同一实现）。
- `link` 模式改 profile `package.json` 前留 `.bak-dsh-link-<ts>`。
- `--json` 给出机器可读报告（profile / target / files / copy / remove / verify / next）。

## 用法

```bash
# 1) 开发模式（推荐给"改代码的人"）：把 profile 依赖切成 link:<repo>
npm run dsh:link
# 之后每次改完：
npm run dsh:reload          # = build + reload + verify

# 2) 发布形态：按 npm 包文件清单覆盖安装目录（不碰 runtime/ext）
npm run dsh:install
npm run dsh:install -- --dry-run --json     # 先看计划
npm run dsh:install -- --no-build           # 已经 build 过

# 3) 只验证
npm run dsh:verify

# 4) 顺带把 Blender 扩展放进 user_default（可选）
npm run dsh:install -- --with-addon
npm run dsh:install -- --with-addon --blender-version 5.3
```

典型输出：

```text

target   C:\Users\<user>\.dsh\pkgs\dsh-blender-plugin-3.3.0

下一步   刷新 DSH 页面…；Gateway 已换代：若 blender_session 显示 0 会话，跑 action=attach 重新认领
```

### 已验证（2026-11-21，本机）

- 首次 `--mode pack`：复制 1338 / 删除 0，HMR 后 Gateway pid 41352 → 40132，`provenance=current`，catalog 270/38。
- **二次** `--mode pack --no-build --no-reload`：复制 **0** / 删除 0（内容哈希命中 manifest）。
- `--with-addon --dry-run`：正确识别
  `C:\Users\<user>\AppData\Roaming\Blender Foundation\Blender\5.3\extensions\user_default\dsh_blender_bridge`。
- 单测：`tests/unit/js/install-dsh.test.ts`（5 条：依赖解析、merge/protected、profile 解析、Blender 版本目录、CLI dry-run 不落盘）。

## 还能更快（未做，按需）

1. **增量编译**：给两个 tsconfig 加 `incremental` + `tsBuildInfoFile`（实测 runtime 2.2→0.8 s、host 1.4→0.7 s，整包 build 4.7→~1.6 s）。缓存放 `lib/`（已被 gitignore），需确认 `check-build` 不把它当产物。
2. **清单缓存**：`npm pack --dry-run --json` 每次 ~1.4 s；可按 `package.json.files` + 目录 mtime 缓存文件清单。
3. **发布 tarball**：发布流水线附 `*.tgz`，安装端 `--from <tgz>` 免编译（适合无 Node 工具链的机器）。
4. **attach 自动化**：Gateway 换代后会话记录清空，脚本拿不到宿主调用方身份（host/session/agent），只能提示；要彻底免手，需要 DSH 插件管理器在重组合后自动认领（宿主侧能力）。
5. **DSH 插件管理器 API**：如果宿主暴露 `plugin install/update` 的本地 API，本脚本可退化成一行调用（现在的 `dsh plugin add` 走 npm registry，源码 checkout 仍需要本脚本这条路）。
